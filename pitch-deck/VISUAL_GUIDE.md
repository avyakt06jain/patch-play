# Visual direction

## Format

- Use 16:9 widescreen.
- Keep a 0.55-inch safe margin.
- Use exactly four prototype screenshots in the main deck.
- Slides 1, 6, and 7 should use typography and simple editable shapes instead of images.
- Avoid decorative stock images.

## Color system

- Base background: `#070D16`
- Raised navy: `#0E1B29`
- Gamer cyan: `#52DFE1`
- Coder amber: `#FFC078`
- Failure red: `#FA7285`
- Verified green: `#72E5A0`
- Main text: `#DCEBF0`
- Muted text: `#7890A1`

Use cyan and amber to distinguish roles. Reserve red for a real failure and green for a tested or verified state.

## Typography

- Cover title: 50–58 pt.
- Slide titles: 32–38 pt.
- Body text: 19–23 pt.
- Code and technical labels: at least 16 pt.
- Use Bahnschrift or Aptos Display for titles, Aptos or Arial for body text, and Consolas for code.

## Screenshot treatment

- Preserve each screenshot’s 16:9 aspect ratio.
- Crop only quiet outer margins.
- Retain role headers and the relevant semantic state.
- Use a one-point border matching cyan, amber, red, or green.
- Do not place text over code, test results, incident evidence, or victory overlays.
- Use each selected screenshot only once.

## Visual rhythm

- Slide 1: minimal typographic cover.
- Slides 2–5: one unique screenshot per slide.
- Slide 6: four editable campaign bands.
- Slide 7: typographic close using P1, D2, and VERIFIED.

## Animation

- Use simple fades only.
- Reveal process text one section at a time when useful.
- Keep screenshots static.
- Avoid transitions that compete with the live demo.
